# DiskMap v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build DiskMap v1. It's a free, open-source Windows app that shows a drive as a treemap, explains the things it recognizes, and removes only those things, safely and with undo.

**Architecture:** A UI-free class library, `DiskMap.Core`, holds everything testable: scanning, the treemap layout, recognition rules, safety rails, quarantine, removal, and settings. It's covered by xUnit tests that run against temporary fixture folders. `DiskMap.App` is a thin, unpackaged, self-contained WinUI 3 shell over Core. It has four tabs: Explore (the default), Clean up, Quarantine, and Settings. The app has one process, which runs either unelevated or elevated after a relaunch.

**Tech Stack:** .NET 10 (current LTS), C#, WinUI 3 (Windows App SDK, self-contained, unpackaged), CommunityToolkit.Mvvm, xUnit, System.Text.Json.

**Spec:** `docs/superpowers/specs/2026-11-02-diskmap-design.md`

## Global Constraints

- Windows 10 1809+ (`TargetPlatformMinVersion` 10.0.17763.0) and Windows 11, x64. Target framework: `net10.0-windows10.0.19041.0`.
- The developer's C: drive has about 2.5 GB free. The SDK, NuGet packages, build output and caches must live on D:. Set `NUGET_PACKAGES=D:\nuget\packages` and `DOTNET_CLI_HOME=D:\dotnet-home`, and install the SDK to `D:\dotnet`.
- No network access of any kind: no telemetry and no update check.
- English only. All UI strings go in `src/DiskMap.App/Strings/en-US/Resources.resw`.
- Settings live in `%LOCALAPPDATA%\DiskMap\settings.json`.
- Undo setting values: Off (0), 3 or 7 days. The default is 3.
- Removal commands, used verbatim:
  - `DISM /Online /Cleanup-Image /StartComponentCleanup /ResetBase`
  - `DISM /Online /Cleanup-Image /AnalyzeComponentStore`
  - `powercfg /hibernate off`
- Sizes are allocated size on disk. Hardlinked files count once, and cloud-only placeholders count as 0.
- Never remove anything that doesn't match a rule. Never follow a reparse point (junction or symlink) during scan or removal.
- Bulk eligibility is decided per rule: `Method == Quarantine` and `Label` is `Safe` or `Rebuildable`. If undo is Off, a bulk removal still runs, but its single confirmation says the files will be deleted permanently.
- Tests must never touch real user folders. Use `Path.GetTempPath()` fixture trees and a `UserContext` that points into the fixture.
- License: MIT.
- Work on a branch named `v1`, never on `main`.

## Review Focus

1. **A file is in use during removal** (for example, an open browser cache). That file is skipped, everything else in the item is still removed, and the result reports the bytes that were skipped. Covered in Task 7, `QuarantineRemove_SkipsLockedFile`.
2. **Junction loops during a scan** (`Application Data` → `AppData\Roaming`, user-made junctions). The scan finishes and doesn't count anything twice. Covered in Task 2, `Scan_DoesNotFollowJunction`.
3. **Access denied on folders during a scan** (System Volume Information, other users' profiles while unelevated). The scan continues, and the folder shows with its readable size. Covered in Task 2, `Scan_ContinuesPastAccessDenied`.
4. **Restoring when the original path exists again** (for example, `node_modules` was reinstalled). Restore never overwrites. It restores next to the original as `<name> (restored)`, or `(restored 2)` and so on. Covered in Task 6, `Restore_WhenTargetExists_UsesRestoredSuffix`.
5. **Paths longer than 260 characters**, which are common in deep `node_modules` trees. Scan and quarantine both handle them. Covered in Task 2, `Scan_HandlesLongPaths`, and Task 6, `Add_HandlesLongPaths`.
